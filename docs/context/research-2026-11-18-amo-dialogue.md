# 아모 대화 방식 문헌 조사 (2026-11-18)

대표 지시(2026-11-18): "대화 형식과 말투에 대해 추리소설 특화된 챗봇 논문 찾고 대화방식 개발해". 구현은 `backend/src/modules/chatbot/harness/amo-style.ts`.

**확인 수준** — 전문(부분) = arXiv HTML 본문에서 해당 절을 읽음 / 초록 = 초록만 읽음 / 서지 = 제목·저자만 확인 / 인용 = 다른 논문이 인용한 내용으로만 확인. arXiv 본문·검색과 ACL Anthology(전체 서지 파일 + 논문 쪽)는 열렸고, Semantic Scholar API는 이번 세션 내내 429(호출 제한)로 막혔다.

## 결론 먼저

- **추리소설 전용 챗봇의 말투·대화 형식을 다룬 논문은 찾지 못했다.** "Watson 같은 동반자" 대화 에이전트, 한국어 해요체 챗봇의 말투 연구, 휴대폰 채팅 답변 길이의 사용자 연구도 찾지 못했다. 아래 규칙은 옆 분야(답을 숨기는 튜터, 진도 인식 독서 보조, 아첨·공손성, 서스펜스·호기심) 근거를 옮겨 온 것이라 **효과는 추정**이다.
- 가장 강한 근거는 "프롬프트만으로는 답을 숨기지 못하고, 모델 밖의 결정적 검사가 필요하다"는 튜터 연구다. 이미 하네스(판정·암시 검사)가 이 방향이며, 이번에는 형식도 같은 방식(낱말 검사)으로 붙였다.

## 발견

1. **질문식(소크라테스식) 튜터 연구는 그대로 옮기면 안 된다.** 튜터의 질문은 교사가 아는 정답으로 학생을 이끄는 것이 목적이다(1·2·6). 아모에게 그 방식은 결정 23이 금한 "답을 실은 되묻기"(ask_leading_question)다. 가져올 것은 "답을 대신 말하지 않는다"와 "모델 밖 검사" 두 가지뿐이다.
2. **압박·아첨은 모델 기본 성향이다**(5·7). 독자가 조르거나 가설을 내밀면 동의 쪽으로 기운다. 말투 지침으로는 막지 못하고 출력 검사가 막아야 한다(2). 형식 규칙은 판정 검사보다 약한 층으로 둔다.
3. **페르소나는 거절을 부드럽게 하는 데 쓴다**(2). "판단하지 않을게요"를 차갑지 않게 말하는 것이 말투의 역할이고, 말투가 금지 규칙과 부딪히면 규칙이 이긴다.
4. **서스펜스·호기심은 불확실성과 정보 공백에서 온다**(18·19·20·22). 칭찬("일리 있어요"), 가능성 견주기, "중요한 단서" 같은 평가어는 독자 대신 불확실성을 줄인다. 이미 막는 것들이며, 이번에 아모 자신의 말에 평가어를 쓰지 않는 규칙을 더했다.
5. **말투는 흔들리고, 낱말 표지로 잴 수 있다**(8·9·11). 한국어 LLM은 공손형을 과하게 쓰거나 상대에 따라 편해진다. 문장 끝 어미로 해요체·합쇼체·반말을 세는 것은 싸고 오탐이 적지만, 대사 인용 때문에 막는 데 쓰기에는 불안하다 → 기록만.
6. **휴대폰 채팅은 짧은 직접 답을 기대한다**(21, 간접). 되묻기·선택지 남용은 짜증을 부른다. 직접 근거는 없어 길이 예산은 기록만 하고 자르지 않는다.

## 아모에 적용한 규칙

| 규칙 | 코드 | 강도 | 근거 강도 |
| --- | --- | --- | --- |
| 같이 읽는 친구, 해요체, 자신은 "아모"·"저" (AI·모델로 자신을 설명하지 않음) | `AMO_STYLE_RULES`(시스템 지침), `register_banmal`·`register_formal`·`ai_self_reference` | 지침 + 기록만 | 중간(8·9·11) |
| 물은 사실 먼저, 쪽수는 근거 있는 사실에만 | 지침. 쪽수 상한은 기존 `page_beyond_cutoff` | 지침 | 중간(13·21) |
| 유형별 길이 예산(사실·가설 4문장/300자, 범인·작품 밖 3문장/240자, 자세히 청하면 두 배) | `LENGTH_BUDGET`, 질문마다 `amoTurnGuidance`, `over_length` | 지침 + 기록만 | 약함(21, 직접 연구 없음) |
| 되묻기는 행동 단계표가 `ask_open_question`을 허용한 유형에서 열린 질문 하나까지 | `multi_question`, `question_not_in_ladder` | 2개 이상 → 1회 재생성(재생성 답에 남아도 그대로 내보냄). 허용 안 된 유형의 되묻기 → 기록만 | 중간(1·2·21) |
| 이모지 금지 | `normalizeAmoText` → `stripped_emoji` | 지우고 내보냄 | 약함(제품 판단) |
| 청하지 않은 제목·글머리표 금지 | `stripped_markdown` (표지만 지우고 줄은 남김) | 지우고 내보냄 | 약함(제품 판단) |
| 아모 자신의 말에 평가어(단서·결정적·수상한·중요한·알고 보니·복선) 쓰지 않음 | 지침, `evaluative_word` (배치 검수 평가어와 같은 목록) | 지침 + 기록만. 막는 것은 기존 `steering_hint` | 중간(4·19·20) |
| 출력 검사는 화면에 보이는 글자로 본다(굵게·이모지가 낱말을 끊어도 판정·쪽수·암시를 잡음) | `plainForGuard` → `guardAnswer` | 기존 검사 강화 | 코드 확인(화면이 마크다운을 그림) |

**바꾸지 않은 것** — 근거 범위는 데이터 선택 단계에서만 건다(R4). 형식 지침에는 쪽수 상한 문구가 없다. 새 런타임 LLM 호출 종류는 없고(R9), 되묻기 재생성은 기존 챗봇 재생성 1회 흐름 안에서만 일어난다. 모든 응답 경로는 고친 뒤의 글로 출력 검사를 거친다(절대 규칙 11).

## 한계·남은 것

- 위 규칙의 효과(재미·몰입·추리 지속)는 측정하지 않았다. 실제 모델 답으로 `evaluation/chatbot-harness/style-unjudged.json` 11건을 사람이 읽어 판정해야 한다(T3과 같은 방식).
- 여러 턴에 걸쳐 조르는 압박(5)은 아직 시험 세트에 없다.
- 낱말 검사라 뜻으로만 드러나는 암시와 모델 사전 지식(A10)은 잡지 못한다.
