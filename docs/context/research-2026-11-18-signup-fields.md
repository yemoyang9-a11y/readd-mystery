# 로그인 시점·가입 항목 조사 — 국내외 전자책 플랫폼 (2026-11-18)

대표 지시(2026-11-18): "처음부터 로그인 창 띄우지 말고 작품을 보려거나 MY 페이지에서 로그인하려고 할 때 로그인창 띄우고, 로그인창에서 받아야 할 정보 같은 것들은 다른 전자책 플랫폼에서 가져와."

DESIGN.md의 "새 화면 전에 3곳 이상 조사" 규칙에 따른 기록이다. 앞선 조사 [research-2026-11-18-new-screens.md](research-2026-11-18-new-screens.md) 1장(로그인 화면 모양)을 이어서, 이번에는 **언제 로그인시키나**와 **가입 때 무엇을 받나**를 본다.

## 0. 조사 방법과 한계

- **가입 화면을 직접 연 서비스는 없다.** 이 세션 네트워크에서 `ridibooks.com`, `policy.ridi.com`, `www.millie.co.kr`가 열리지 않았다(이름 확인 실패). 그래서 각 서비스의 **개인정보 처리방침·이용약관·고객센터 공지를 웹 검색 결과(요약·발췌)로** 확인했다. 표의 근거는 전부 `2차`(검색 요약)다.
- 처리방침은 "수집 항목"이지 "화면에 칸이 몇 개 있나"가 아니다. 화면 순서·문구는 확인하지 못했다.
- 검색 결과에 옛 버전 방침(2016~2023)이 섞여 있다. 아래 표는 가장 최근으로 보이는 버전을 적고, 확실하지 않으면 그렇게 적었다.
- 법률 해석은 언론·법무법인 해설 요약이다. 법률 검토가 아니다. **실제 약관·처리방침 문안과 필수 동의 구성은 대표(법무) 확인이 필요하다.**

## 2. 법 맥락 (해설 요약 — 법률 검토 아님)

- **만 14세 미만**: 개인정보보호법 제22조의2 — 법정대리인 동의가 필요하다. 조사한 국내 6곳 모두 14세 기준을 두고, 14세 미만은 법정대리인 절차를 따로 둔다. 우리는 법정대리인 절차가 없으므로 **"만 14세 이상입니다" 필수 확인**으로 14세 미만 가입을 받지 않는다.
- **동의는 항목별로 나눠 받는다**: 제22조 제1항. 선택 동의를 안 했다고 서비스를 거부하면 안 된다(제22조 제5항). → 마케팅 수신은 **선택**, 가입을 막지 않는다.
- **광고성 정보**: 정보통신망법 제50조 — 광고성 정보를 보내려면 미리 동의를 받아야 한다. → [선택] 마케팅 정보 수신.
- **필수 동의 관행 개선**: 2023-09-15 시행 개정으로 계약 이행에 필요한 개인정보는 동의 없이 처리할 수 있고(제15조 제1항 제4호), 개인정보위는 2024-09 "계약에 필요한 정보에 굳이 필수 동의를 받을 필요가 없다"고 안내했다. 그래도 국내 플랫폼 대부분(예스24·알라딘·윌라)은 여전히 "[필수] 개인정보 수집·이용 동의"를 받는다. 이번에는 대표가 정한 묶음(필수 개인정보 수집·이용 포함)을 그대로 두고, **법무 검토 때 "동의"를 "고지"로 바꿀지 결정할 항목**으로 남긴다. ([신&김 뉴스레터](https://www.shinkim.com/kor/media/newsletter/2039), [뉴스서울](https://newsseoul.co.kr/news/view/1065588011287541) `2차`)
- **최소 수집**: 제16조 — 목적에 필요한 최소한만 받는다. 이름·생년월일·휴대폰은 결제·성인인증·법정대리인 절차가 생길 때 그 시점에 받는다(리디의 "성인 작품을 볼 때만 성인인증" 방식).

## 3. 로그인 시점 — 언제 띄우나

| 참고 | 무엇을 하나 | 근거 |
| --- | --- | --- |
| 리디 | 성인인증은 가입 때가 아니라 성인 작품을 열 때 받는다(필요할 때 묻기) | 위 처리방침 `2차` |
| Apple HIG | "로그인은 가능한 한 늦게" — 둘러보기는 로그인 없이 | [Sign in with Apple](https://developer.apple.com/design/human-interface-guidelines/sign-in-with-apple) (앞선 조사) |
| Duolingo | 가입을 뒤로 미뤄 먼저 써 보게 해 일간 이용자가 늘었다 | [First Round Review](https://review.firstround.com/the-tenets-of-a-b-testing-from-duolingos-master-growth-hacker/) `2차` (앞선 조사) |
| 전자책 서점 일반(리디·예스24·교보·알라딘 웹) | 목록·작품 소개는 비회원도 보고, 구매·뷰어·서재에서 로그인 | 일반 경험 — 이번 세션에서 화면으로 다시 확인하지 못함 |

**정한 것** — 홈·검색·서재 목록·작품 소개(PC 작품 페이지)·커뮤니티 허브(잠긴 모습)·MY·이용 가이드는 비회원도 연다. **작품을 여는 순간**(브리핑 `/books/:id/briefing`, 읽기 `/books/:id/read`, 완독자 이야기방 `/books/:id/community`)과 **MY의 로그인/회원가입 버튼**에서 로그인 화면을 띄운다. 휴대폰은 작품 주소(`/books/:id`)가 곧장 브리핑으로 가므로 책을 누르면 바로 로그인 화면이 뜬다.

**전체 화면 vs 시트** — 전체 화면으로 둔다. 근거: ① 조사한 서비스가 모두 별도 화면(페이지)으로 로그인·가입을 받는다 ② 가입은 칸 4개 + 약관 5줄이라 시트로는 휴대폰 키보드와 겹쳐 길어진다 ③ 주소(`/login?next=`)가 있어야 카카오·구글 로그인에서 돌아오고 새로 고침해도 남는다. 대신 위 왼쪽에 **닫기(✕)** 를 두어 들어오기 전 화면으로 돌아간다(직접 주소로 들어왔으면 홈).

각 줄 오른쪽 **보기**를 누르면 그 문서가 아래에서 올라오는 시트로 열린다(밀리의서재가 선택 항목에 바텀 시트를 쓰는 방식 — 앞선 조사). 문서는 **초안**이다 — 제목에 "초안"을 달고, 대표가 법무 문안을 주면 바꾼다.

**동의 저장** — 서버 `user_consents`(계정·종류·버전·동의 여부·시각)에 남긴다. 버전은 `2026-11-18-draft`. 필수 셋 중 하나라도 빠지면 가입 API가 400(`CONSENT_REQUIRED`)을 돌려준다.

**카카오·구글 첫 로그인** — 카카오싱크를 쓰지 않는 지금은 "로그인 뒤 서비스 자체 약관 화면" 방식을 쓴다. 로그인을 마쳤는데 필수 동의가 없으면(새 OAuth 계정, 이 변경 전에 가입한 계정) 같은 약관 묶음만 있는 동의 화면(`/consent`)을 띄우고, 동의하면 원래 가려던 곳으로 간다. 닫으면 로그아웃하고 돌아간다. 카카오싱크로 카카오 화면 안에서 받는 방식은 카카오 비즈 앱 전환·검수가 필요해 미뤘다.

## 5. 가져온 것 / 버린 것

**가져온 것**
- 둘러보기는 비회원, 작품을 열 때 로그인(리디의 "필요할 때 묻기", Apple HIG).
- 이메일 = 아이디, 비밀번호 다시 입력(윌라·Amazon).
- 약관 묶음: 전체 동의 + [필수] 셋 + [선택] 마케팅, 줄마다 보기(국내 6곳 공통 구성).
- 만 14세 기준(국내 6곳 공통).
- 비밀번호 조합 규칙(예스24) — 단, 조합 종류는 영문·숫자 둘로 줄임.
- OAuth 첫 로그인 뒤 빠진 약관만 받는 화면(카카오싱크 문서의 "미동의 약관만 다시 요청").

**버린 것**
- 휴대폰 본인인증·CI/DI(밀리의서재·예스24·알라딘·교보): 지금 목적에 필요 없고 비용·외부 업체가 든다.
- 별도 아이디(리디·예스24·알라딘·교보): 칸만 늘어난다.
- 약관 동의를 첫 단계 화면으로 따로 떼는 예스24식 다단계: 한 화면에 칸 4개 + 약관 묶음이면 충분하다.
- 회색 부연 설명(DESIGN.md 금지): 비밀번호 규칙은 설명 문장이 아니라 3개 상태 표시로만 둔다.
