# 커뮤니티 화면 참고 조사 — 국내 커뮤니티 앱·사이트 실제 화면 비교 (2026-11-19)

> 대표 지시: "커뮤니티 화면이 엉망." → 국내 커뮤니티 서비스의 실제 화면(목록·글 보기·댓글·글쓰기)을 나란히 비교하고, 다음 단계에서 시안을 만든다.
> 스포일러 방지는 조사하지 않았다. 커뮤니티는 끝까지 읽은 독자만 들어오기 때문이다.
> 이 문서는 조사 결과와 제안만 담는다. 코드는 바꾸지 않았다. 무엇을 할지는 대표가 시안을 보고 정한다.

## 1. 어디를 어떻게 봤나

### 방법
- 휴대폰 화면(아이폰 15 Pro Max 크기, 한국어)으로 공개된 웹 화면을 열어 캡처했다. 로그인·글 올리기·양식 제출은 하지 않았다.
- 로그인해야 보이는 앱(에브리타임·블라인드·왓챠피디아)은 앱스토어에 올라온 공식 홍보 화면을 내려받았다.
- 캡처는 모두 [`docs/validation/2026-11-19-community-refs/`](../validation/2026-11-19-community-refs/)에 있다(19장, 약 4.7MB). 가로 645px로 줄였다.

## 3. 여러 서비스에 공통으로 보이는 것 → 우리 문제와 짝짓기

| 공통으로 보이는 것 | 쓰는 곳 | 우리 문제 |
| --- | --- | --- |
| 글 목록은 카드 없이 **줄 목록**, 한 화면 6~10개 | DC·당근·블라인드 | ④ 큰 카드 3개 |
| 한 줄에 **제목(또는 첫 문장) 굵게** + 미리보기 1줄 + 작은 정보 한 줄(이름·시간·공감·댓글) | 당근·블라인드·DC | ④ |
| 글쓰기는 **오른쪽 아래 둥근 버튼** 또는 머리줄·탭바 안. 목록을 가리지 않음 | DC·당근·블라인드 | ⑤ 글쓰기 막대 |
| 빈 상태는 **문장 + 할 일 하나** | 당근·그믐 | ⑦ 버튼 두 개 |
| 머리줄은 **그 방 이름**(한글). 장식 글씨 없음 | 전부 | ② 영어 장식 글씨 |
| 사람이 고른 닉네임, 또는 **글 안에서만 쓰는 번호 + 글쓴이 표시** | 전부 / 에브리타임·스레드 | ③ "독자 d2d2" |
| 말머리·주제가 **4개 이상**, 또는 해시태그 | DC·당근·그믐 | ⑥ 말머리 2개 |
| **인기 글을 위에 따로**(BEST, 개념글, 실시간 인기) | 네이버·카카오·DC·블라인드 | 목록에서 좋은 글이 묻힘 |
| 방 고르는 화면에 **최근 글 한 줄 + 숫자**(참여자·댓글·조회) | 그믐 | ① 허브가 이름 + 글 N뿐 |
| 글 보기 아래 **고정 댓글 입력창** | 왓챠피디아·그믐·블라인드 | (지금도 있음 — 유지) |
| 댓글이 **어느 부분을 보고 쓴 글인지** 표시 | 카카오페이지(회차) | 추리 노트처럼 쪽수·장을 붙일 수 있음 |

## 4. 우리 커뮤니티에 쓸 제안

표시: **[화면만]** = 프론트만 바꾸면 됨 · **[서버 필요]** = 새 데이터나 API가 필요 · **[대표 결정]** = 정해 주셔야 함

화면 규칙은 지킨다: 화면에 "AI"·"싸비" 글자 없음, 작은 회색 도움말 없음, 아모 그림에 손 없음(커뮤니티에는 아모가 나오지 않는다).

### 제안 1. 책 이야기방 목록을 "줄 목록"으로 — [화면만]
- 카드 테두리를 없애고 줄 사이에 가는 선만 둔다. 한 줄 높이 약 88~96px → 휴대폰 한 화면에 **6~7개**(지금 3개).
- 한 줄 구성 (위→아래):
  1. **말머리 칩 + 첫 문장 굵게 1줄** (제목 칸이 없으니 본문 첫 줄을 제목처럼)
  2. 본문 다음 내용 1줄(말줄임)
  3. 닉네임 · 시간 · 공감 N · 댓글 N (한 줄)
- 3번 줄은 회색 작은 글씨로 흐리게 하지 말고, 14px에 본문보다 한 단계 옅은 색까지만 쓴다(작은 회색 도움말 금지 규칙).
- 참고: 당근 [11](../validation/2026-11-19-community-refs/11-daangn-list.png), DC [01](../validation/2026-11-19-community-refs/01-dcinside-list.png)
- 덧붙임: DC·당근·블라인드는 모두 **제목 칸**이 따로 있다. 제목 칸을 넣으려면 [서버 필요] + [대표 결정].

### 제안 2. 글쓰기 버튼을 오른쪽 아래 둥근 연필 버튼으로 — [화면만]
- 화면 폭 전체 막대를 없애고, 오른쪽 아래에 지름 56px 둥근 버튼(연필 아이콘 + "글쓰기" 글자)을 둔다. 목록 끝에 버튼 높이만큼 여백을 둬서 마지막 글이 가려지지 않게 한다.
- 다른 안: 머리줄 오른쪽에 "글쓰기"(DC). 둘 다 두는 것도 DC가 쓰는 방식이다.
- 참고: DC [01](../validation/2026-11-19-community-refs/01-dcinside-list.png), 블라인드 [16](../validation/2026-11-19-community-refs/16-blind-store-popular.png)

### 제안 3. 이름 방식 바꾸기 — [서버 필요] + [대표 결정]
- 지금 "독자 9407"은 서버가 독자 번호를 섞어서 만든 4글자다(`backend/src/modules/community/router.ts`의 `nicknameFor`).
- 안 A (추천): **가입할 때 받은 닉네임**을 쓴다. 가입 항목에 닉네임이 이미 있다(2026-11-18 결정, 계정 표 `display_name`). 커뮤니티 글이 계정 닉네임을 가져오도록 서버를 바꿔야 한다.
- 안 B: 에브리타임처럼 **글 하나 안에서 "익명1·익명2"**, 글쓴이 댓글은 "글쓴이"로 표시. 범인 이야기를 편하게 하려면 이쪽이 낫다.
- 어느 안이든 **댓글에 "글쓴이" 표시**는 함께 넣기를 권한다(에브리타임·스레드·DC 모두 있음). 누가 글쓴이인지는 서버가 알려 줘야 한다 [서버 필요].
- 참고: 에브리타임 [15](../validation/2026-11-19-community-refs/15-everytime-store-board.png), 스레드 [14](../validation/2026-11-19-community-refs/14-threads-post-replies.png)

### 제안 4. 말머리 4개로 늘리기 — [서버 필요] + [대표 결정]
- 지금: 범인 추리 / 감상.
- 제안: **범인 추리 / 감상 / 질문 / 명장면**
  - 질문: "5장 편지는 누가 쓴 거예요?" 같은 다 읽은 독자끼리의 질문
  - 명장면: 기억에 남는 장면·문장 이야기
- 서버의 글 종류 목록(`KINDS`)과 저장 규칙을 바꿔야 한다. 이름은 대표가 정한다.
- 참고: DC 말머리, 당근 주제, 그믐 해시태그 — [11](../validation/2026-11-19-community-refs/11-daangn-list.png), [05](../validation/2026-11-19-community-refs/05-gmeum-list.png)

### 제안 5. 목록 맨 위에 "공감 많은 글" 2~3개 — [화면만]
- 네이버·카카오의 BEST, DC의 개념글처럼, 최신순 목록 위에 공감 많은 글 2~3개를 따로 보여 준다. 이미 있는 "인기순" 목록 기능을 그대로 불러 쓰면 된다.
- 그러면 위쪽의 "최신순/인기순" 전환은 빼도 된다(화면이 단순해짐).
- 참고: 네이버 [08](../validation/2026-11-19-community-refs/08-naverwebtoon-comments.png), 카카오 [10](../validation/2026-11-19-community-refs/10-kakaopage-comments.png)

### 제안 6. 허브(책 고르기)에 최근 글 한 줄 — [서버 필요]
- 지금은 책 이름 + "글 5"뿐이다. 그믐 모임 카드처럼 **최근 글 한 줄 미리보기 + 마지막 글 시각 + 글 수·댓글 수**를 보여 준다.
- 허브 API가 책마다 "가장 최근 글 첫 줄·시각"을 함께 줘야 한다.
- 아직 들어갈 수 없는 책(끝까지 안 읽은 책)은 미리보기를 보여 주지 않는다(지금처럼 잠금).
- 참고: 그믐 [05](../validation/2026-11-19-community-refs/05-gmeum-list.png)

### 제안 7. 영어 장식 글씨 빼고, 머리줄은 책 이름으로 — [화면만]
- "CASE FILES", "CASE CLOSED"를 지운다. 허브 제목은 "커뮤니티", 책 방 머리줄은 "← 탁류" + 아래에 "다 읽은 독자 이야기방"처럼 한글로만.
- 참고: 모든 서비스가 머리줄에 방 이름만 둔다.

### 제안 8. 빈 상태는 문장 하나 + 버튼 하나 — [화면만]
- "아직 글이 없어요. 첫 이야기를 남겨 주세요." + 오른쪽 아래 글쓰기 버튼 하나만. 가운데 "첫 글 쓰기" 버튼을 빼서 같은 버튼이 두 개 보이지 않게 한다.
- 문장은 본문과 같은 크기·밝기로(회색 작은 글씨 금지).
- 참고: 당근 [13](../validation/2026-11-19-community-refs/13-daangn-empty-comments.png)

### 제안 9. 글 보기·댓글 정리 — 대부분 [화면만], 답글·댓글 공감은 [서버 필요]
- 순서: 말머리·이름·시간 → 본문 → **공감·댓글 아이콘 한 줄** → "댓글 N" 머리 → 댓글 → 아래 고정 입력창(지금 있음, 유지).
- 댓글 정렬 "등록순/최신순"(당근) — [화면만]으로 가능한지 확인 필요(서버가 순서를 고정해 주면 [서버 필요]).
- 답글(대댓글)과 댓글 공감은 지금 없다 → 넣으려면 [서버 필요]. 첫 시안에서는 빼고 다음 단계로 미루기를 권한다.
- 참고: 당근 [12](../validation/2026-11-19-community-refs/12-daangn-post.png), 왓챠피디아 [19](../validation/2026-11-19-community-refs/19-watchapedia-store-comment.png), DC [03](../validation/2026-11-19-community-refs/03-dcinside-comments.png)

### 제안 10. 글쓰기는 대화상자 대신 전체 화면 — [화면만]
- DC처럼 전체 화면, 오른쪽 위 "올리기", 위에 말머리 칩, 아래 넓은 입력칸. 휴대폰 자판이 올라와도 입력칸이 가려지지 않는다.
- 말머리별 입력칸 안내 문장(지금 "범인과 그렇게 생각한 이유를 적어 보세요")은 그대로 둔다.
- 참고: DC [04](../validation/2026-11-19-community-refs/04-dcinside-write.png)
