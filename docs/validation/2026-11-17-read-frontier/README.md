# 차례 읽기 기준점 화면 캡처 (2026-11-17)

FR-PRG-003 — 목차로 기준점보다 뒤로 건너뛸 때의 확인 창(`TocJumpDialog`)과, 싸비 맨 위의 읽은 범위 확인 카드(`FrontierConfirmCard`)를 휴대폰 화면에서 실제로 띄워 찍은 것이다.

## 찍은 방법

- Vite 개발 서버(5174)에 Playwright(Chromium)로 접속했다. 화면 390×844, 배율 2, 터치 기기 설정.
- 백엔드는 띄우지 않았다. `http://localhost:3000/**` 요청을 Playwright가 가로채 JSON으로 답했다. 따라서 **화면 확인용**이고, 서버의 기준점 판정을 검증한 것은 아니다.
- 시험 도서: 68쪽, 5장(1–12 / 13–24 / 25–40 / 41–55 / 56–68). 본문과 인물 이름은 자리 채움 글이다.
- 시작 상태: 진입 쪽 13, 서버가 돌려준 `applied_cutoff` 13.

## 확인한 것

- 확인 창과 카드의 숫자(41쪽, 13쪽)는 응답 값과 같다.
- 확인 창: 390×844와 390×664 모두 화면 안에 다 들어오고, 버튼 3개가 한 줄씩 쌓이며 잘리지 않는다.
- 카드: 두 크기 모두 글과 버튼 2개가 한 줄에 들어가고 잘리지 않는다. 버튼 높이 44px.
- 카드가 뜨면 그 높이(약 124px)만큼 탭 내용 영역이 줄어든다. 390×664에서는 관계도 아래 조작 버튼 줄이 화면 아래에 걸리지만, 탭 내용 영역이 스크롤되어 닿을 수 있다.
- 요청 순서: `progress {page: 13}` → `progress {page: 41, from_page: 13}`(claim 없음) → `graph` → `progress/confirm {choice: "furthest"}` → `graph` 재조회.

## 참고

- 가로챈 응답의 관계도 간선에는 `semantics`를 넣지 않았다. 캡처에 선이 보이지 않는 것이 이 때문인지는 확인하지 않았다.
