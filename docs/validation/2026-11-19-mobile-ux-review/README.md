# RE:ADD 모바일 화면 사용자 관점 평가 (2026-11-19)

- 대상: 운영 배포본 https://yemoyang9-a11y.github.io/readd-mystery/
- 환경: ego lite(Chromium), iPhone 크기 흉내 390×844, 터치 흉내 켬. 실제 iPhone Safari가 아님.
- 계정: 사용자 본인 계정(로그인은 사용자가 직접). 「가상범인」 66/68쪽 상태에서 시작.
- 눌러 본 순서: 홈 캐러셀 → 작품 보기 → 로그인 → 브리핑(목차 펼침) → 읽기(목차 손잡이, 보기 설정, 스와이프 넘김) → 싸비(인물관계도·노드 탭, 추리 노트·작성 창, 타임라인, 아모) → 커뮤니티 → 책 이야기방 → 피드백 → MY → 이용 가이드 → 404
- 스크린샷은 이 폴더의 번호순 PNG.

## 먼저 고치면 좋은 것

### 1. 싸비로 들어가는 길이 안 보인다 — [08-reader.png](08-reader.png)
읽기 화면 양옆 가운데에 작은 세로 막대 손잡이만 있다. 왼쪽(목차)과 오른쪽(싸비)이 똑같이 생겨서 구분되지 않는다. 추리 노트·관계도·아모가 이 서비스의 핵심인데, 처음 온 독자는 여기를 누를 이유를 찾기 어렵다.
- 제안: 오른쪽 손잡이에 아이콘이나 짧은 글자(예: "싸비")를 넣는다. 첫 진입 때 한 번만 손잡이를 가리키는 안내를 띄운다.

### 2. 한국어 단어가 중간에서 잘린다 — [06](06-briefing-scrolled.png), [08](08-reader.png), [15](15-timeline.png), [16](16-amo.png)
"나용/귀", "모르겠으/면", "악/마", "붙잡/힌다", "끼어/든다", "안에/서"처럼 줄 끝에서 단어가 쪼개진다. 브리핑 요약, 본문, 타임라인, 아모 말풍선 모두 그렇다. 추리소설에서 인물 이름이 두 줄로 갈라지면 누가 누군지 읽는 흐름이 끊긴다.
- 확인: 브리핑 문단의 `word-break`가 `normal`이다.
- 제안: 본문 계열에 `word-break: keep-all`(긴 영문·URL 대비로 `overflow-wrap: anywhere`도 함께)을 준다. 본문은 출판물 느낌을 원하면 양쪽 정렬과 함께 검토한다.

### 3. 브리핑에서 무엇을 먼저 할지 흐리다 — [05-after-login.png](05-after-login.png)
빨간 테두리의 "커뮤니티" 카드가 줄거리 요약보다 위에서 가장 눈에 띈다. 정작 주된 행동인 "이어서 읽기"는 테두리만 있는 버튼이다. 몇 쪽까지 읽었는지(66/68쪽) 같은 진도 표시도 화면에 없다.
- 제안: "이어서 읽기"를 채운 버튼으로 만든다. 커뮤니티 카드는 요약과 추리 노트 아래로 내린다. 머리 부분에 "66 / 68쪽 · 5장" 같은 진도를 한 줄 넣는다.

### 4. 관계 설명 목록이 중복돼 헷갈린다 — [12-graph-node.png](12-graph-node.png)
이몽란을 누르면 유불란이 "사랑(의심·주장)", "연인(사실)", "사랑(의심·주장)"으로 세 줄 나온다. 박영민도 "부부", "윗사람이다", "욕망"으로 세 줄이다. 머리글의 별칭도 "유불란 (탐정소설가·탐정소설가 유불란 씨·유불란 씨)"처럼 같은 말이 반복된다. 관계 이름도 "친구·사랑"(명사)과 "윗사람이다"(서술)가 섞여 있다.
- 제안: 사람별로 한 줄로 묶고, 사실과 의심을 같은 줄 안에서 구분한다. 별칭은 중복을 걸러 대표 1~2개만 보인다. 관계 이름은 명사형으로 통일한다(데이터 정리 문제일 수 있음).
- 관계도 안에서는 박영민·박병국이 둘 다 "박"으로 표시돼 원 안 글자만으로는 구분되지 않는다. 연결선이 없는 김영애·진대성·박병국이 그래프 공간을 차지하는 점도 아쉽다.

### 5. 로그인으로 넘어갈 때 설명이 없다 — [04-after-open.png](04-after-open.png)
"작품 보기"를 누르면 왜 로그인이 필요한지 설명 없이 바로 로그인 화면이 뜬다. 구글·카카오 버튼은 같은 회색 테두리에 로고도 없어서 한눈에 구분되지 않는다. 비밀번호 찾기 링크도 없다.
- 제안: "로그인하면 읽은 곳과 추리 노트를 기억해요" 같은 한 줄을 넣는다. 카카오는 노란색, 구글은 로고처럼 각 서비스의 표시를 쓴다. 비밀번호 찾기를 추가한다.

## 다듬으면 좋은 것

6. **화면마다 톤이 다르다.** 홈·브리핑·커뮤니티·MY는 어두운 톤이고 읽기·싸비는 밝은 종이 톤이다. 404는 예전 밝은 디자인에 "서재로" 버튼이 있는데 지금 메뉴에는 "서재"가 없다 — [23-404.png](23-404.png). 읽기 화면이 밝은 건 의도로 볼 수 있다. 다만 404는 새 디자인으로 바꾸고 "홈으로"로 고치는 게 좋다.
7. **홈 캐러셀 전환이 어긋난다.** 다음 책으로 넘기면 제목·소개 글이 먼저 바뀌고 표지는 약 1초 뒤에 따라온다(넘긴 0.9초 뒤 캡처에서 제목은 「타원형의 거울」, 가운데 표지는 아직 「가상범인」). 두 가지를 동시에 전환하는 게 좋다 — [01](01-home.png), [02b](02b-home-next-settled.png).
8. **아모 말풍선 글자가 12px로 작다.** 본문은 18px이다. 휴대폰에서 읽기 편하려면 15~16px 정도는 돼야 한다 — [16-amo.png](16-amo.png).
9. **읽기 화면에 지금 위치 정보가 쪽수뿐이다.** 상단에 책 제목이나 장 이름("5장 의외의 결말")이 없어서, 오랜만에 들어오면 어디인지 바로 알기 어렵다.
10. **목차 팝오버가 좁다.** 장 제목이 두 줄로 꺾이거나 "현장부재증명(現場不在證…"처럼 잘린다. 뒤 배경을 어둡게 하지 않아 본문 글자와 겹쳐 보인다 — [09-reader-toc.png](09-reader-toc.png).
11. **노트 작성은 가운데 창, 보기 설정은 하단 시트로 다르다.** 휴대폰 키보드가 올라오면 가운데 창의 입력칸·저장 버튼이 가려질 수 있으니 하단 시트로 통일하는 게 안전하다(실기기 키보드는 확인 못 함) — [14-note-form.png](14-note-form.png), [10-reader-settings.png](10-reader-settings.png).
12. **커뮤니티 빈 상태에 글쓰기 버튼이 두 개다.** "첫 글 쓰기"와 하단 "글쓰기"가 함께 있다. 하나로 줄인다 — [19-community-room.png](19-community-room.png).
13. **피드백 화면 안내가 부족하다.** 입력칸 하나뿐이라 무엇을 적으면 좋은지, 답을 받는지 알 수 없다. "버그, 바라는 기능, 헷갈렸던 점" 같은 예시 한 줄을 넣는다 — [20-feedback.png](20-feedback.png).
14. **MY에 내 독서 기록이 없다.** 이름·로그아웃·보기 설정만 있다. 읽는 중인 책과 진도, 내 추리 노트 모아보기가 있으면 MY 탭을 찾을 이유가 생긴다. "탈퇴"가 로그아웃 바로 옆에 있는 것도 실수로 누르기 쉽다 — [21-my.png](21-my.png).
15. **영어 장식 라벨의 뜻이 전달되지 않는다.** "CASE FILE · READER", "CASE CLOSED", "FILE · EMPTY"는 분위기용이지만, 한국어 독자에게는 뜻이 전해지지 않는 장식이다. 유지한다면 바로 옆 한국어 제목이 충분히 크고 분명해야 한다.

## 잘 된 점

- 스와이프 넘김이 자연스럽다(오른쪽→왼쪽으로 밀면 66→67쪽).
- 보기 설정 하단 시트는 글자 크기·줄 간격·배경 고르기가 명확하다.
- 타임라인은 장별 요약과 "지금 읽는 곳 · 5장 — 다 읽으면 정리돼요" 처리가 스포일러 규칙과 잘 맞고 이해하기 쉽다.
- 관계도에서 인물을 누르면 연결선과 노드가 강조되고 아래 목록이 바뀐다.
- 아모의 추천 질문 칩 덕분에 처음 쓰는 사람도 뭘 물어볼지 알 수 있다.
- 공개 전 책은 "곧 공개" 비활성 버튼으로 분명하게 구분된다.
- 이용 가이드(8단계 코치 투어)와 데모 책 「멈춘 시계」가 첫 사용을 잘 이끈다.

## 확인하지 못한 것

- 아모 실제 답변: AI 호출과 운영 기록이 생겨서 질문을 보내지 않았다.
- 노트 저장, 커뮤니티 글쓰기, 피드백 제출: 운영 데이터가 생겨서 하지 않았다.
- 실제 iPhone Safari 렌더링, 키보드가 올라올 때의 배치, 관계도 두 손가락 확대·축소, 홈 화면 추가 실행.
- 카카오 로그인 왕복 자체는 사용자가 직접 했다.

## 남은 흔적

- 스와이프 확인으로 진도가 66→67쪽으로 바뀌었다가 "이전 페이지"로 66쪽으로 되돌렸다. 마지막 저장 위치는 66쪽이다.
- 브리핑·읽기 화면 진입 기록(세션·조회 로그)이 운영에 남았을 수 있다.
- 커뮤니티 "완독자 이야기"는 66쪽 상태에서도 들어가졌다. 코드상 완독 판정이 "가장 멀리 읽은 쪽 ≥ 마지막 쪽"(추리소설판 기준)이라, 이 계정이 예전에 68쪽까지 읽어 둔 것으로 보인다. 그래서 스포일러 누출로 판단하지 않았다(계정 진도 기록을 직접 확인하지는 않았다).
